# Go2 本体里程计与 LIO-SAM 建图

在机器人终端执行 `bash ~/go2-detail/noetic/start.sh --go2`。每次启动会创建单独的地图归档。在 Foxglove 连接终端打印的 Wi-Fi 地址，建图与导航共用仓库根目录的 [Go2.json](../Go2.json)。右侧相机面板订阅 `/camera/display/compressed`，建图时显示已转正的 D435i 彩色画面。

地面锁定后，三维建图 `/go2_visual/ground/dense_map`、实时扫描 `/go2_visual/ground/scan` 和局部细节 `/go2_visual/detail/local` 都只显示标定初始地面上方超过 15 cm 的回波，并去掉少于 8 个 5 cm XY 连通格的孤立小块，墙面上部、横梁等高处回波随原始量程显示。配准和地面标定使用前方过滤后的完整高度数据；新地图显示和导航栅格另外应用下述人工确认通行带。主 PCD 保留完整配准几何。

## 前行通行带（所有新建地图，旧地图不改）

用户已确认前进沿途的近处区域无障碍，启动脚本统一启用此建图规则：
以机身中心为起点，沿地面投影后的机身朝向，前方 **0–1m**、左右各
**0.5m** 的矩形清除全部高度点云。不是地图固定 X 方向，也不是雷达光心。
`--go2` 使用同一扫描时间戳的 Go2 本体位姿确认前进，再用 LIO 实际扫描
位姿和物理安装外参定位范围。静止、纯转向、倒退、缺数据不会新增前进确认。
保存时将前进记录间的优化关键帧按时间顺序接成连续扫掠通道，导航转换时清除原来
一截一截之间残留的静态障碍格。弯路经过实际中间关键帧，不直接连接弯道首尾。
扫描断流、位姿跳变或明显倒退处分段，不跨过这些缺失区清图。
默认 LIO 和原生模式同样启用；规则与地图名无关。

通行带随关键帧保存，回环后跟随优化位姿更新。显示和导航转换对全部历史点
应用累计范围，所以早先在远处看到的路面点不会再次覆盖已清除区域。
此规则是人工确认的地图清理，不是自动证明区域安全；范围内真实障碍也会
从静态地图删除。导航实时全周障碍检测及足迹碰撞检查继续工作。

已撤销保存时逐点拟合地形的步骤，不再生成 `survey_terrain.npz`。
原始点云只读一遍完成写入，完成后回填 PCD 头部。每个新版本仅保存一份
完整 PCD（`dense.pc_geometry=full_registered_returns`），附 v2
`surveyed_corridor.json`（路径、安装外参和地面标定）、逐帧索引和优化轨迹。
原始扫描 SQLite 仍在本轮运行归档中。定位和三维环境显示使用完整 PCD；
`corridor_application=navigation_grid_only` 表示通行带只影响派生导航栅格。
将整条路的全部高度回波直接从定位 PCD 删除，会减少匹配几何并造成地图与
实时扫描不一致，不能保证对 GICP 无影响。

导航使用相同的连续扫掠几何生成可通行格；不按通道外接矩形扩大清理范围。
导航静态栅格、实时避障和过滤显示统一按保存的初始地面过滤 0–15 cm 回波；
取消局部坡面/地形拟合及轨迹高度推算，不再加载旧地形文件。已有 v1 地图的
坐标契约继续核对，但不依赖其地形 NPZ。白色连续通行带保持原几何形状。
这些是公共规则，对所有地图生效，不修改旧存档；首次使用更新代码自动重建
导航缓存。真实低矮物体和孤立小块也会被过滤，起点平面以上超过 15 cm 的
坡面仍可能进入障碍候选。定位的主 PCD 不进行这项导航过滤。

当前建图若已经记录通行带，不必重走：保持建图窗口，只停止仍在执行的旧
保存命令，拉取更新后重新执行 `bash ~/go2-detail/noetic/save_map.sh farm2`。
同名保存会创建新的版本目录，已有 `farm2` 版本不会被覆盖；导航默认选择
最新完整版本。建图实时预览仍按采集时的离散确认区显示，连续连接在保存和
导航转换时完成。保存日志应显示“保留完整定位点云，不执行地形拟合”和逐帧进度。

已经保存了清理版地图、但原运行的 `dense/scans.sqlite` 仍在机器狗上时，无需
重新去现场或启动 ROS，可恢复相同名称的新版本：

```bash
/usr/bin/python3 ~/go2-detail/noetic/restore_map_geometry.py farm2
```

`farm2` 可换成任意地图名或明确的版本目录。恢复只采用原版本扫描索引中的
扫描和原版本优化关键帧，不混入后来新增扫描或回环变化。原通行带、标定和
旧版本保留；恢复成功后导航默认选用新版本。缺失原运行数据库、来源/时间戳/
锚点/安装外参不匹配时直接报错，不猜测其他数据库。输入早已过滤的后方回波
无法恢复。已是完整几何的版本重复执行不会再生成一份。

更新只需拉取一次，之后建图、保存、导航命令不访问 GitHub，无需编译 C++：

```bash
bash ~/go2-detail/noetic/start.sh --go2
# 保留建图窗口，另开终端保存
bash ~/go2-detail/noetic/save_map.sh farm2
# 保存成功后停止建图，再启动导航
bash ~/go2-detail/navigation/start.sh farm2
```

## 建图排除机身后方（所有新建地图）

`start.sh --go2`、默认 LIO 模式和 `--native` 共用 `mapping_front_filter.py`。
原始 `/livox/lidar` 先按真实 `base_link <- 雷达帧` 外参转换判断方向，
仅把机身 `X>=0` 的回波送往 `/go2_mapping/lidar_front`。分界是随机器人
转动的机身中心横截面，不是地图的固定 X 方向，也不是倾斜雷达的原始 X。
前方高处回波沿用原有量程，没有新增高度上限。缺少或运行中改变安装外参
时暂停送帧，不能退回未过滤点云。

过滤在 LIO-SAM 特征提取和回环之前完成，因此注册扫描、实时显示、稠密
SQLite 归档、导出的 PCD 及其派生导航栅格均不会重新加入该次扫描的后方
回波。没有修改 C++，无需重新编译。被排除回波的 XYZ 置零，仅保留原始
点顺序、逐点时间偏移和扫描时间范围；LIO 正数 `lidarMinRange` 和原生建图
的零距离检查会排除这些占位，不会写入原点，也不会当成空闲清障射线。
保存时 `live/mapping_parameters.json` 记录筛选规则和实际使用的外参。

旧地图保留原样，历史跟随者残影需要重新建图；改配置不能识别旧 PCD 中
哪些点属于人。此规则也会排除后方静态物体，在其进入机身前方视野时才
会建入地图；它不是动态人物识别。导航的实时输入仍保留全周观测和原有
碰撞检查。定位输入断流、时钟异常及目标点 frame 错误需要分别排查。

1. Go2 站稳。终端应出现“已接通 Go2 原生里程计”和“已按扫描时间将 Go2 本体位姿用作 LIO-SAM 建图初值”。预测节点按特征帧时间查找原始 Livox 帧名，通过本体位姿插值和安装外参得到雷达位姿，然后把初值交给原有的 LIO-SAM 地图优化节点。MID-360S 的 IMU 用于旋转去畸变。启动程序只运行工作区现有的三个 LIO-SAM 可执行文件。
2. 若提示缺少安装外参，另开终端运行 `python3 ~/go2-detail/noetic/mount_setup.py`。工具可从本机工作区已展开的实机 URDF 提取固定变换，或接受实测的机身到雷达 XYZ（米）与 RPY（度）。选定的标定保存在 `~/.config/go2/body_from_lidar.json`，当前建图会自动重试。如果已有实机 URDF，也可在启动前设置 `GO2_ROBOT_URDF`。D435i 与雷达之间的标定还需要对应的相机到机身变换，0.50 米只表示雷达离地高度。
3. 等“地面已锁定”后，用原来的遥控方式向前走几米，再停稳。在另一终端执行 `bash ~/go2-detail/noetic/start.sh --check-stop`，保持静止 10 秒。它会报告本体、地图中的模型和 LIO 位姿相对停稳首帧的最大位移与转角，以及同时刻雷达预测与配准的距离。还应在 Foxglove 观察同一墙角或立柱有无重影。回环测试另需重访先前地点，短距离走停只能验证局部稳定性。
4. 模型位姿取自 Go2。首次同戳雷达配准建立地图与本体里程计坐标系的关系；回环等优化改写已有关键帧时更新这个关系。全局回环可同时调整模型在地图中的位置与旧点云的位置。本体本身的漂移会反映在模型上，LIO 配准误差会反映在地图上。

右侧状态面板每秒更新五次。已有 11321 同名发布者优先。DDS 或 11311 上存在的定位布尔值和状态文本可随本体桥接送入面板。`/localization/valid` 沿用旧工程的先验地图定位语义，单独建图时为 false，过期的有效报告也回到 false。`/localization/status` 显示本体与建图位姿，坐标系随数值标出。`/operator/status` 显示实际速度、可用的运动模式/步态/错误码，以及最近收到的操作节点报告和接收时间。速度和运动状态码不能证明运动控制已启用。

已在运行上一版时，可在第二个终端执行 `bash noetic/start.sh --status`，读取本轮已有的本体与建图里程计。下次用 `--go2` 启动时会自动启动状态节点，并接入外部状态来源。

## 保存一份导航源地图

保留本轮建图窗口，让 Go2 停稳，在另一终端执行 `bash ~/go2-detail/noetic/save_map.sh inroom`。成功时打印 `~/go2_maps/inroom/日期时间_随机后缀/inroom.pcd` 的实际路径。每次执行生成一个独立版本。

每个版本只有一个点云文件。二进制 `inroom.pcd` 保存本轮完整配准回波，字段为 x、y、z、intensity。导出程序在 SQLite 的同一只读事务中取点、优化关键帧及通行带记录，逐帧转换到归档标出的世界坐标系。逐帧点索引 `scans.csv` 和优化轨迹 `keyframes.csv` 用纳秒时间戳对应点云行与关键帧。人工确认通行带以元数据保留，导航栅格应用清理；定位源几何不会被该规则删除。旧版未标记归档仍按原方式导出。

运行参数、TF、里程计快照和本次可追溯的标定收在同一目录。相机内参、机器人描述和回环可视化标记按实际接收情况保存。`manifest.json` 记录坐标系、点数、扫描范围和缺失项。进入版本目录可用 `sha256sum -c SHA256SUMS` 校验。这个三维源图可用于点云配准；新 Nav2 流程所需的二维占用栅格稍后从这份图及标定、轨迹派生。未提前记录的原始 LiDAR/IMU、RGB 和高频本体里程计历史无法事后补录。
